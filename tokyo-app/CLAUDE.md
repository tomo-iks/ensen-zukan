# (仮称) 東京街歩きアプリ

上京してきた大学生・社会人が、沿線に沿って東京の街を歩きながら学び、その記録を残すアプリ。

## 位置づけ(決定)
- 既存アプリ「沿線まち図鑑 v22」を**土台に改善する**(新規に作り直さない)。現状の課題を洗い出してから、改善範囲を決める

## 前提(判断基準)
- 課題: 東京の街をよく知らない
- 目標: 主要駅の街の特徴を人に説明できる / 気分で散歩先を選べる
- 成功指標: 記録を5分以内(最初のリリース) / 気分から3操作以内(第2段階)
- 迷ったら「ペルソナの課題解決と成功指標に寄与するか」で決める。寄与しないものは作らない。

## スコープ
- Must: 街歩きの記録 / 訪問済みの街の一覧(沿線ごと)
- Should(第2段階): 気分から街を選ぶ
- 同梱データ: 中央線快速(立川まで)・山手線の46駅。カテゴリ(雰囲気タイプ)は元Excelにあり、街の特徴・気分タグは下書き→人が確認
- 元データの遊び場・季節・スポット・参考写真は含める(決定済み)。**食事は「店名・ジャンル・最寄り駅・食べログへのリンク」のみ**(評価・予算・メニュー・紹介文は載せない。REQUIREMENTS.md を参照)
- 既存アプリの記録操作「行った(行った/行きたい+日付+メモ)」「ピン(写真付きの地点記録)」「お散歩(GPS経路の記録)」を踏襲する。詳細は REQUIREMENTS.md「既存アプリの記録操作」を参照
- **上記以外の機能は、追加前に必ずユーザーに確認する**

## 技術
- Webブラウザ / HTML + JavaScript(ビルドなし) / 保存: IndexedDB(端末内のみ)
- 街データは同梱JSON。サーバー・アカウントなし。外部ライブラリは原則使わない
- 詳細は PERSONA_GOALS.md / REQUIREMENTS.md / DESIGN.md を、必要な時だけ参照する

## 作業ルール(エラー最小化)
- 変更前に対象ファイルを読む。推測で書かない。不明点は確認する
- 1回の依頼では1つの目的だけを変更する。依頼外の変更・リファクタをしない
- 変更後は、動作確認の方法と結果を報告する。確認できないことは「未確認」と書く
- 保存失敗時は原因と対処を表示し、入力を消さない
- 街の特徴などの事実データは推測で書かない。下書きは人の確認を経て確定する
- 外部由来のデータ・写真は、出所ごとの表示義務を守る(OSM: © OpenStreetMap contributors と ODbL / 写真: 作者・ライセンス・元ページへのリンク)
- 食べログ由来の評価・予算・メニュー・紹介文は、許諾なく公開物に含めない
- 禁止: 写真・記録の外部送信、依頼外のファイル変更、無断の仕様変更

## トークン効率
- 回答は結論から簡潔に。同じ説明を繰り返さない
- 全体を読み直さず、必要なファイル・範囲だけ読む
- 差分だけを提示し、ファイル全体の再掲をしない
- 仕様が決まっている事項は再質問しない。新しい決定のみ文書に追記する
