# 開発前の構想詰めインタビュー

通常の開発工程(企画→目標→要件定義→設計→品質ルール→命名)の順に、本筋で必須な項目から詰める。

## 優先順位(上が埋まるまで下へ進まない)
1. **必須**: 課題 → ペルソナと困りごと → 目標 → 成功指標(測れる形) → Must機能(各機能が指標に紐づくか) → 非ゴール
2. **重要**: 利用シーン → 技術スタック(最小構成か) → エラー方針 → 確認方法
3. **任意(最後・仮称で可)**: 制約 → 禁止事項 → UI規約 → アプリ名

## 進め方
1. 既存の文書(CLAUDE.md、README、PERSONA_GOALS.md 等)があれば先に読み、既出の内容は聞き直さない。
2. 不足・曖昧・矛盾を優先度順に最大5件挙げる。推測で埋めない。
3. 質問は1回に最大3問。選択肢を添え、「分からない/後で」も選べるようにする。
4. 各機能について「成功指標に寄与するか」「単純さを損なわないか」を確認する。Mustは5個以内に絞る。
5. ユーザーが答えた内容だけを反映する。勝手に仕様を足さない。
6. 必須項目が埋まったら、次を作成して内容を確認してもらう。
   - `CLAUDE.md`(判断基準・スコープ・技術・作業ルール・トークン効率ルール。短く)
   - `PERSONA_GOALS.md` / `REQUIREMENTS.md` / `DESIGN.md`

## 完了条件
必須項目がすべて埋まり、全機能が成功指標に紐づいていること。任意項目の未記入は完了を妨げない。
